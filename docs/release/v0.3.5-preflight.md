### Re-test after the subscription change (2026-10-06 16:00 +08:00)

The product owner reported that the subscription was enabled and the models
were working, so three real generation attempts were issued. All three failed
from this client:

| Attempt | Result |
| --- | --- |
| `gpt-image-2.5-sunburst` (prompt, 1024x1024) | HTTP 500 `read_response_body_failed` — “read: connection reset by peer” |
| `gpt-image-2.5-flare` (prompt, 1024x1024) | HTTP 500 `do_request_failed` — “upstream error: do request failed” |
| `gpt-image-2.5-sunburst` (prompt, 600s client timeout) | no response at all within 600 seconds |

Redacted evidence: `docs/release/aihub-route-evidence-2026-10-06-retest.json`.

The failure pattern (reset while reading the upstream body, upstream
`do_request_failed`, and a 600-second hang) points at the AIHub image-group
upstream channel rather than the key or CrossGen: either the upstream provider
is not actually wired up for these deployments, or the gateway read timeout is
shorter than the model's generation time. No attempt returned an image.

Recommended checks on the AIHub side:

1. Confirm the image group has a working upstream channel for
   `gpt-image-2.5-sunburst` / `gpt-image-2.5-flare`.
2. Check the gateway read timeout for image generations; GPT Image 2.5 can take
   minutes, so a short timeout will always surface as a reset or
   `do_request_failed`.
3. Confirm whether AIHub exposes an asynchronous job mode for these models.

## Video technology preview (after the feature-catch-up freeze)

### Route feasibility finding (2026-10-06)

The approved AIHub aggregation API currently exposes **no video model at all**.
The full catalogue (21 ids, read 2026-10-06) contains text and image models
only:

- image: `qwen-image-2.1`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`
- text: gpt-5.5 / 5.6-sol / 5.6-terra / 6-sol / 6.1-sol, claude-opus-4-8 /
  opus-5 / sonnet-4-6 / sonnet-5, gemini-3.1-pro / 3.8-flash,
  deepseek-v4.1-flash, qwen3.8-flash, glm-5.3-flash, grok-4.6 / 4.7,
  nowo-qwen-3.8, step-5-preview
- video: none

Because the v0.3.5 plan requires every real video gate to run through AIHub and
forbids bypassing it without explicit product-owner approval, the single
"high-value sample" for the video preview cannot be selected from the currently
approved provider. WP-0 (route freeze) is therefore blocked on a product-owner
decision:

1. approve a different provider/route for the video preview (which changes the
   plan's provider constraint), or
2. keep AIHub-only and defer the video preview until AIHub exposes a video
   deployment, or
3. move the video preview out of v0.3.5 entirely and ship v0.3.5 as the
   post-release consolidation plus General image-to-image.

The video preview remains in scope for v0.3.5 but is sequenced after the
absorbed post-release features are frozen and verified. These items are not
guarded by the release-evidence verifier until the video route is frozen and
its gates are added to the ledger:

- [ ] 冻结唯一视频路线、唯一样机与唯一后处理思路。
- [ ] 定义视频 submit / poll / download / cancel / timeout / recovery 状态与诊断分类。
- [ ] 打通 poster 提取与最小本地后处理，失败/取消/重试均可清理。
- [ ] ResultViewer / History / Gallery 使用 poster 预览视频，不影响图片路径。
- [ ] 记录 ffmpeg-static 或等价包装对三平台包体、签名和公证的影响。
- [ ] 视频能力具备 feature gate、显式成本确认和回滚路径。
