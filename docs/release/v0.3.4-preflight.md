## Rollback

- AppLink 解析或确认失败时不写入 provider state。
- media root 迁移失败时不更新 `storage.mediaRoot`，源目录保留。
- 视频/GIF 预览失败时提供下载/打开目录动作，不影响图片 Canvas。
- 若候选包出现图片回归，停止发布并回退到上一个已批准的 release。

## Local launch hygiene

- Replacing a packaged `app.asar` does not update an already-running Electron
  process. Quit all CrossGen processes before reopening a rebuilt candidate.
- For local candidate inspection, launch the explicit package path
  `release/mac-arm64/CrossGen.app`; do not infer the loaded version from a
  process path that may belong to an older process.
- The user-level `~/.local/bin/crossgen` launcher must resolve to the same
  candidate package. An older `/Applications/CrossGen.app` can remain installed
  for rollback, but it must not be the active debug entry.
- `http://localhost:5174/` is not CrossGen on this machine; it is owned by the
  separate Corgnitor Management Vite project. CrossGen source preview uses the
  repository's own dev-server command and port.

## Local launch incident: wrong 0.3.3 package

On 2026-09-14 the local app unexpectedly showed the retired 0.3.3 design. The
source tree and `origin/main` were already at `b2cae542`; the symptom came from
launching a different app bundle:

| Bundle | Version | `app.asar` SHA256 | Role |
| --- | --- | --- | --- |
| `/Applications/CrossGen-legacy-20260914/CrossGen-0.3.3.app` | 0.3.3 | `4df9fddb3fd51e12d1b7a98575aa4aa84affd545ff67e1512a07e5ca07c7ed02` | Retired legacy package |
| `/Applications/CrossGen.app` | 0.3.4 | `a4d71de5721a2bd550dacfd2afda44376cf82c96456e1e0d6e5de2e1dc535d39` | Separate installed package |
| `release/mac-arm64/CrossGen.app` | 0.3.4 | `e84896c1f5a1273486b542ccf6e17b989529506d4bfa1bc2ff4e963ce859c9ff` | Current candidate |

All three main bundles used the same `com.bliveren.crossgen` Bundle ID, and
LaunchServices retained additional old worktree, temporary-test, and mounted
volume registrations. As a result, `open -a CrossGen` was not a trustworthy
debug selector. The old 0.3.3 bundle also lacks the current GPT Image 2.5 and
Sketch markers, which confirms that the visual regression was package identity,
not a source-code rollback.

The fix was to unregister the retired bundles, garbage-collect stale
LaunchServices entries, explicitly register the current candidate, and then
retest both an absolute-path launch and `open -a CrossGen`. The resolved
application path and running process now point to `release/mac-arm64/CrossGen.app`,
and the packaged CLI reports `appVersion: 0.3.4`. Old files were retained for
rollback; no destructive deletion was performed.
