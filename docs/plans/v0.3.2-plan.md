## Decision

v0.3.2 has one user promise:

```text
Make image task execution visible, diagnosable, cancellable, retryable, and recoverable.
```

v0.3.1 introduced the durable image queue shared by desktop, CLI, and MCP. v0.3.2 turns that runtime into a visible desktop workflow without expanding the release into agent productization, video, media migration, or provider-native adapter sprawl.

## Scope

Must ship:

- Minimal queue UI: queued, running, failed, cancelled, interrupted, retryable.
- Worker and concurrency visibility: online worker hosts, current running count, configured concurrency limit.
- Generation waiting state: elapsed seconds, attempt number, current stage, and user cancellation.
- Provider diagnostics: operation, model, route, input image count, mask usage, timeout, attempts, retryability, charged-retry risk, next actions.
- Reference image preflight: local metadata, request-size estimation, non-destructive downsampling for request copies, temp cleanup.
- Restart recovery: stale running tasks become interrupted and never silently retry.
- History/Gallery continuity: failed tasks preserve prompt, parameters, inputs, error summary, partial outputs, and retry entry points.
- CLI/MCP compatibility: queue and job status may expose richer fields, but the v0.3.1 JSON envelope and existing field names remain valid.

May ship if low-risk:

- Queue and generation-related card hover/active state unification.
- Generation overlay breathing glow and completed-edge flash.
- Error/retry popover polish using the existing floating-surface design system.
- Notice success/error polish and `aria-live`.
- `prefers-reduced-motion` coverage for new transitions.

Will not ship:

- CLI enable/disable UI, PATH detection, App-move repair, or MCP client setup UI. These belong to v0.3.3.
- Video, GIF, ffmpeg, `OutputAsset` migration, or media-aware ResultViewer. These belong to v0.3.4+.
- New large provider-native adapters.
- Background daemon, HTTP server, or local port.
- Silent paid retry.
- Global visual redesign unrelated to task reliability.

## Data Contract Draft

The following fields are v0.3.2 implementation targets. They are additive and must not remove v0.3.1 fields.

```ts
type TaskDiagnosticCategory =
  | "auth"
  | "billing"
  | "rate_limit"
  | "timeout"
  | "safety"
  | "unsupported_capability"
  | "route_unsupported"
  | "provider_empty_output"
  | "provider_schema"
  | "network"
  | "cancelled"
  | "unknown";

interface TaskDiagnostic {
  category: TaskDiagnosticCategory;
  message: string;
  providerMessage?: string;
  operation: "text-to-image" | "image-to-image" | "guided-region";
  providerKind: "openai" | "openai-compatible" | "gemini" | "custom";
  modelId: string;
  route?: string;
  inputImageCount: number;
  hasMask: boolean;
  timeoutMs: number;
  attemptIndex: number;
  retryable: boolean;
  chargedRetryRisk: boolean;
  nextActions: string[];
}

interface ReferencePreflightSummary {
  id: string;
  original: {
    mime: string;
    width?: number;
    height?: number;
    bytes: number;
    hasAlpha?: boolean;
  };
  request: {
    mime: string;
    width?: number;
    height?: number;
    bytes: number;
    hasAlpha?: boolean;
    downsampled: boolean;
  };
  reason?:
    | "within_limits"
    | "pixel_limit"
    | "byte_limit"
    | "provider_limit"
    | "mask_preserved"
    | "mask_dimension_mismatch";
}
```

## Phase 0: Baseline And Contract Freeze

Deliver:

- Freeze queue snapshot shape.
- Freeze diagnostic categories and next-action rules.
- Freeze reference preflight limits and temp cleanup rules.
- Create a real-provider gate matrix covering provider route x model x operation x timeout x output.
- Confirm UI adoption scope from the external `ui-optimization-plan.md`.

Acceptance:

- The implementation tasks below have stable input/output shapes.
- No v0.3.3+ work is included in v0.3.2 acceptance.

## Phase 1: Queue Observability Core

Deliver:

- Reusable queue snapshot builder for CLI/MCP/desktop.
- Counts for queued/running/succeeded recent/failed/cancelled/interrupted.
- Concurrency summary: configured max, running global, provider caps.
- Worker host summary: online/offline by lease and kind.
- Queue job public summary: elapsed, attempt, max attempts, retryable, charged-retry risk, stage, source.
- Additive CLI/MCP queue status and job status fields.

Acceptance:

- `pnpm verify:queue-concurrency-smoke`
- `pnpm verify:cli-mcp-smoke`
- `pnpm verify:agent-integration-smoke`
- Unit tests for snapshot counts, live workers, elapsed calculation, retryability.

## Phase 2: Minimal Queue UI

Deliver:

- Generation overlay with elapsed seconds, attempt number, stage, and cancel action.
- Compact queue entry in the desktop UI showing running/queued/failed counts.
- Queue panel listing recent tasks with cancel/retry/details actions.
- Retry confirmation when another paid provider request may be made.
- Error detail popover/dialog with diagnostic and next actions.

Acceptance:

- Renderer smoke covers queued/running/failed/interrupted.
- Running and queued tasks can be cancelled.
- Failed/interrupted tasks can be retried only after confirmation.
- Queue UI does not cover API config, tag manager, parameter dialog, or Gallery pagination controls.

## Phase 3: Provider Diagnostics And Timeout Discipline

Deliver:

- Operation-level route diagnostics for text-to-image, image-to-image, and guided-region edit.
- Capability preflight before provider call for unsupported reference/edit/mask combinations.
- Error normalization for empty output, billing/quota, timeout, route unsupported, provider schema, network, cancelled, and unknown.
- Strict respect for user-configured timeout budgets.
- Mask/guided-edit warning for compatible endpoints that may not support official edit/mask routes.

Acceptance:

- Text-to-image success is not treated as proof that image-to-image is supported.
- `data: null` and missing image outputs produce `provider_empty_output`.
- Billing/quota errors are not retryable by default.
- User cancellation is not shown as a provider failure.
- Provider tests cover the main diagnostic categories.

## Phase 4: Reference Image Preflight

Deliver:

- Metadata extraction for local reference images.
- Request-copy downsampling for oversized images without mutating originals.
- Separate conservative handling for masks.
- UI-visible preflight summary.
- Queue/History retention of preflight summary.
- Temp cleanup on completion, failure, cancellation, and next app startup.

Acceptance:

- Large reference fixtures send smaller request copies.
- Original Gallery/History/local files are unchanged.
- Oversized images that cannot be safely processed are blocked before provider spend.
- Mask preflight has dedicated coverage.

## Phase 5: History/Gallery Recovery Experience

Deliver:

- History card shows duration and source channel without layout regression.
- Failed cards expose failure details on hover/click without permanent card bloat.
- Interrupted tasks explain app exit or worker loss and provide retry.
- Gallery save, preview, drag-to-reference, tags, and folder behavior do not regress.
- Notice and floating-layer z-index fixes for diagnostic/retry/tag dialogs.

Acceptance:

- `pnpm verify:image-core-regression-smoke`
- `pnpm verify:gallery-mutation-smoke`
- No known right-rail collapse, scroll jitter, or popover clipping regression.
